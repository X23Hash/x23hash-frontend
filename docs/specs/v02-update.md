## 1. 목적과 범위 — PRD

- 해결할 문제: 현재 구현은 v0.1(2026.10.20) 기준입니다. v0.2에서 화면 구성·문구·번호와 일부 기능이 바뀌어 시안과 구현이 다릅니다.
- 진행 방식(사용자 지정): ① 자료 분석과 계획 → ② 화면을 하나씩 시안과 비교해 맞춤 → ③ 필요한 에셋·결정은 사용자에게 요청 → ④ 회의 메모의 항목은 가능한 것부터 진행하거나 조사.
- 포함 범위: 01–08 흐름 66화면과 피드 배경 프리셋 6종. 글 수정·삭제와 내 사진 배경은 1차 출시 포함(자료의 2026.11.19 결정).
- 제외 범위: 보류 화면 9개(쪽지 숨기기 10.01–10.05, 피드 광고 11.01–11.04). 자료는 "화면이 그려져 있어도 만들지 않는다"고 명시합니다. 스토어 등록 이미지, 이벤트 설계, 브랜드 탐색 페이지는 개발 범위 밖입니다.

### 서버 현황(2026-11-24 `GET /v3/api-docs` 조회)

v0.2가 요구하는 다음 항목이 서버에 없습니다. 화면만 먼저 만들 수는 있어도 동작은 서버 반영 후에 가능합니다.

- 글 수정(`updatePost`)·삭제(`deletePost`) 경로 없음. `/api/v1/posts/{postId}`는 GET만 있습니다.
- 게시글 응답(`PostView`)에 `background`·`updatedAt` 없음. 등록 요청(`CreatePostRequest`)도 `body`·`submissionId`뿐입니다.
- 배경 사진 업로드(`uploadBackground`) 경로 없음.

`background`가 없는 글은 자료의 예비 규칙 `(hash(postId) % 6) + 1`로 프리셋을 정하므로, 피드의 프리셋 배경은 서버 없이 먼저 구현할 수 있습니다.

## 3. 구현 설계 — Tech Spec

세부 설계는 각 화면을 시작할 때 해당 통합 스펙에 씁니다. 여기에는 계획 단계에서 확인한 조건만 남깁니다.

- 저장 키: 자료는 `tmx.sim.episode`·`tmx.sim.step`을 예로 들지만 "경로·스키마는 개발 결정"이라고 밝힙니다. 이미 배포된 `x23hash.onboarding.v1`을 유지합니다. 장면 구조가 바뀌므로 저장된 `actionB`는 여운으로 읽어 들입니다.
- 프리셋 배경: 위·아래 색과 빛 번짐 위치가 표로 주어져 있어 이미 설치된 `expo-linear-gradient`와 `react-native-svg`로 그릴 수 있습니다. 그레인 질감 이미지는 에셋이 필요합니다.
- 전체보기 판정은 글자 수가 아니라 실제 렌더 높이(본문 영역 y116–y660) 기준입니다.
- 내 사진 배경: 기기 사진 선택은 네이티브 모듈이 필요해 앱은 새 빌드가 됩니다(웹은 파일 선택). 서버 업로드 경로가 생긴 뒤 진행합니다.
- 글쓰기 미리보기 제거, 문구·화면 재구성은 네이티브 변경이 없어 OTA 대상입니다.
